# Changelog

## Unreleased

- **A playthrough that fights** (console `fight [0|1]` before `route all`; `tools/tour_maps.ps1 -Route -Fight`): the route walker has no god mode; it stops to aim and shoot at the nearest monster that is after the player and in sight (`TD3Game.FightTarget`), with the strongest weapon it has ammo for (`BestFightSlot`: chaingun, plasma gun, machine gun, shotgun, pistol, fists), saves the game every 20 s of quiet and loads that save when the player dies (three deaths after one save: god mode until the next save, counted as a place given up); a monster that doesn't die in 25 s is left. The log says `Fight: target <name> at ...`, `Fight: died at ...`, `Fight: gave up at ...` and at the route's end `Fight: summary: N kills, N deaths, N saves, N places given up (god mode), health, armor, seconds`. It still walks in noclip along the route (through closed doors), so it can meet monsters before the map enables the weapons (Mars City Underground's `no_Weapons` until a trigger): the fight enables them then (log `Fight: the map had the weapons disabled here: enabled`); with only the fists it keeps walking. Mars City Underground played this way: the route done, 16 kills, no deaths, 14 saves, the next map loaded. Console `inventory` says why a weapon can't fire (`weapons disabled`, `influence`, `GUI focus`, `talk focus`).
- **Monsters and projectiles spawned by scripts** (`sys.spawn`): the new entity gets its entityDef's keys and its md5 model (`TDoom3Map.SpawnModelEntity`), a monster its AI script like at map load (`TD3Game.SpawnActor`), and the script places it (`setOrigin`); a spawned projectile flies when the script calls `projectileLaunchProjectile` (its def's speed along the direction, plus the push velocity). Console `call <function>` runs a script function. The test map's script has `test_spawn` (log `Script spawned blob_spawned_1 (monster_test_scripted) with its AI`, `Script launched the projectile ball_spawned_1 (projectile_test)`). Not checked in Resurrection of Evil's boss maps yet.
- **Saved games** (`code/doom3world_save.inc`; console `savegame [name]` / `loadgame [name]`, F6 / F9 for the quick save; files in the user's config directory, `saves/<name>.sav`, text): loading a save loads its map again and puts back the player (place, yaw, health, armor, weapons, clips, ammo, carried items, PDAs, emails, videos, objectives, security, stamina, air, powerups), the script's global variables and, per entity, lights on or off, hidden brush and model entities, monsters' health, death and place, items picked up, triggers disabled, doors locked, the smaller entities (barrels, panes...), trigger counts. The script goes on where it was: the game's clock is the saved one, and when the program is the same the script threads (stacks, frames, waits), the actors' script objects and states, the doors' and script movers' moves, every brush and model entity's place and the delayed activations are put back. Checked in the test map (the map's `main` doesn't start over, the lift goes on from where it was) and in the middle of a fight in Mars City 2 (287 threads; the zombie goes on attacking). Also saved: projectiles in flight (made again from their defs), the weapon in the hand with its script thread and object (it is ready at once), elevators, the lights' shader parameters (colors) and fades, which looping speakers play, `god` / `notarget` / `noclip`. The dead lie where they died: a body that was there falls again as a ragdoll at its place. Not saved: particles and FX in flight, one-shot sounds, decals, a ragdoll's exact pose.
- **Doom 3 BFG Edition data** (`-basepath "<DOOM 3 BFG folder>"`; `code/doom3bfg.pas`): the BFG edition has no source assets, only `.resources` containers of "generated" binaries. `Doom3Files` mounts the containers like PK4s (`_common`, `_ordered`, the sounds with the English speech, every map's) and a source file exists when its binary does; the loaders read the binary into the structures the text loaders fill:
  - `.bproc` (the map's models, precomputed shadow volumes, portals and area nodes), `.bcm` (collision models);
  - `.bmd5mesh` (vertexes in the bind pose with four byte joints and weights, turned into md5 weights relative to their joints; the joints' poses relative to their parents) and `.bmd5anim`;
  - `.blwo` / `.base` (LWO and ASE models as render models: half float texture coordinates, byte normals and colors);
  - `.bimage`: DXT1, DXT5 and the plain formats; diffuse maps stored as YCoCg, normal maps with x in alpha, the alpha test ("coverage") version of a diffuse map for its alpha, cube map sides (camera cube maps turned back). An image name answers as a `.tga`; the result of an image program (`addnormals( a, heightmap( b, 4 ) )`) is read from the file named after it;
  - `.idwav` (Microsoft ADPCM and PCM) decoded to 16 bit WAV;
  - the BFG fonts (`newfonts/<name>/48.dat` with one page, the GUI's font names mapped by the language file's `#font_*` strings).
  - Not read: the Flash menus, HUD and PDA (`.bswf`: the port's own HUD, menu and PDA screen show), Bink videos (`.bik`), binary particles (`.bprt`: the text `.prt` files are there too), model collision files (`.bcmodel`).
  - Unit tests write their own container from the test PK4's map and models (written in the binary layouts, read back and compared with the text versions) plus hand made images and ADPCM blocks.

## 0.12.0

Shadows from big md5 models.

- **md5 shadow hulls**: md5 meshes over 1500 triangles (retail monsters) used not to cast at all, because CGE searches silhouette edges quadratically and again on every animation frame. They now cast with one closed box per joint, around the vertexes the joint moves, shrunk to stay inside the body and moved by a per-joint matrix transform, so their edges never change.
- Console `r_md5ShadowTris <n>`: the triangle limit (reloads the map; 0 makes every md5 model cast with boxes).
- Shots log which monster they hit.
- 296 checks (joint matrices match skinning, boxes are closed and face out, box counts); CI checks the boxes are built.

Still one shadow casting light: more need shadow volume or cube shadow map support for several point lights in CGE (roadmap item 2).

## 0.6.0

Light volumes.

- **Doom 3 light volumes**: lights don't fade with distance any more; like Doom 3 each lights a box (point lights, `light_radius`, `rotation`) or a frustum (projected lights, `light_target` / `light_right` / `light_up`, `light_start` / `light_end`), mapped to the light's texture space like `lightProject`, shaped by projection and falloff curves. Implemented as a per-light CGE shader effect (`PLUG_light_scale`) reading the fragment's world position.
- Lights without a `texture` use Doom 3's `lights/defaultPointLight` / `lights/defaultProjectedLight` when the game data declares them.
- `shaderParm4` is the light shader's time offset, like Doom 3.
- Console `r_lightVolumes [0|1]` reloads the map with plain spherical lights for comparison.
- **Fixed**: a shut door was hidden by portal visibility when seen from the room on its other side (it now belongs to the areas on both sides of its portal).
- Test level: a projected window light, Doom 3-style default light shaders and light images.
- 210 checks (light texture space, projected lights, shapes).

Known limitation: projection and falloff images are approximated by analytic shapes chosen from the image name (CGE doesn't bind textures referenced only by light effects).
